# 会话与上下文

Pi 把一次对话保存为会话。该会话的活动分支为下一次模型请求提供对话历史。使用会话命令可以继续工作、探索另一个分支，或减少发送给模型的历史量。

## 继续或切换会话

除非用 `--no-session` 启动，Pi 会自动保存会话。

```bash
pi --continue
pi --resume
```

`--continue` 打开当前工作目录最近的会话。`--resume` 打开会话选择器。交互模式中，`/resume` 打开同一个选择器，`/new` 开始新会话。

用 `/name` 或 `--name` 给会话起一个可识别的名字。运行 `/session` 查看当前会话文件、ID、消息数、token 用量和费用。

会话选择器支持搜索、重命名和删除会话。它还可以显示路径、改变排序，以及只显示具名会话。快捷键见[按键绑定](keybindings.zh-CN.md#sessions)。

## 选择分支方式

Pi 把条目存储为树，因此回到较早的时间点不会抹掉你离开的那个分支。

| 操作 | 结果 | 适用场景 |
|---|---|---|
| `/tree` | 在当前会话文件内移动 | 相关的备选方案应放在一起 |
| `/fork` | 从较早的用户消息创建新会话 | 备选方案应成为独立的工作 |
| `/clone` | 把活动分支复制到新会话 | 想要当前状态的独立副本 |

在 `/tree` 中选择一条用户消息，其文本会放回编辑器。编辑并提交即可创建另一个分支。选择助手响应或其他条目，则从该条目之后继续，编辑器为空。

离开一个分支时，Pi 可以对它做摘要，并把摘要附加到你进入的分支上。这保留了被放弃路径上的相关工作，又不必包含其中每条消息。

持久化树和条目类型见[会话格式](session-format.zh-CN.md)。

## 管理对话上下文

模型收到的是活动分支，而不是会话文件中的每个分支。Pi 把该历史与系统提示词、发现的上下文文件、可用工具和已加载的技能描述组合在一起。[Pi 的工作原理](how-pi-works.zh-CN.md#context)描述了这些输入如何组装。

页脚显示当前上下文用量。当活动上下文接近模型上限时，Pi 通常会自动压缩（compact）较旧的历史。压缩会添加摘要并保留近期消息。它不会删除原始会话条目。

运行 `/compact` 手动压缩。当摘要需要保留特定主题或决策时，可以附加指令。通过[设置](settings.zh-CN.md#compaction)配置自动压缩和保留的历史。

提供商不可用或无法接受摘要请求时，压缩可能失败。先解决提供商问题，再重新运行 `/compact`。禁用自动压缩不会禁用手动命令。

阈值、保留边界、分支摘要行为和扩展钩子见[压缩参考](compaction.zh-CN.md)。

## 控制会话存储

默认情况下，Pi 把会话存储在 `~/.pi/agent/sessions/` 下，按工作目录分组。用 `--session-dir`、`PI_CODING_AGENT_SESSION_DIR` 或 `sessionDir` 设置选择其他位置。CLI 选项优先级最高。

临时运行用 `--no-session`。临时会话在 Pi 退出后无法恢复。

已知会话路径或 ID 时用 `--session`。要在交互模式开始前从现有会话创建新会话，用 `--fork`。

## 导出或分享会话

用 `/export` 把当前会话写成 HTML 或 JSONL。用 `/share` 上传并获得查看链接。默认情况下，配置了 Radius 认证时 Pi 使用 Radius 产物；否则使用私有 GitHub gist。设置 [`sessionShareDestination`](settings.zh-CN.md#sessions-and-context) 为 `gist` 或 `radius` 可强制指定目的地。

导出或分享之前先审查会话。它们可能包含 prompt、模型响应、工具参数、命令输出、文件内容和扩展消息。

## 报告 bug

运行 `/bug [description]` 为 Pi 开发者准备一份私密报告。你可以包含会话记录、省略它，或让当前模型总结问题。审查任何记录或生成的摘要，因为它们可能包含敏感对话数据。

报告包含环境和提供商配置（不含凭据值），以及记录的错误诊断。通过 `radius.pi.dev` 上传，或把同样的报告导出为 zip 自行检查和分享。上传不需要登录；Radius 认证会把报告归到你的账户，便于开发者跟进。上传失败时，Pi 会提供导出 zip 的选项。
