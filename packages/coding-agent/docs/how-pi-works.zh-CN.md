# Pi 的工作原理

Pi 协调模型请求、工具执行、上下文组装和会话存储。会话（session）是 Pi 对一次对话的记录，包括消息、工具调用与结果、模型切换、压缩（compaction）和其他事件。

会话中的消息和事件构成一棵树。穿过这棵树的每条路径是一个分支（branch）。终止于当前条目的分支是活动分支，为下一次模型请求提供历史。

## Agent 循环

提交的消息被加入活动分支。Pi 用系统提示词、活动分支、可用工具和模型设置构建模型请求，然后通过所选提供商发送。

提供商流式返回助手响应，其中可以包含文本和工具调用。Pi 记录响应、执行每个工具调用并记录结果。这就完成了一个回合（turn）。如果工具结果或排队消息需要再一次模型请求，Pi 就开始另一个回合。否则本次运行结束。

Steering 消息在当前助手回合之后进入。Follow-up 消息在 agent 完成其待办工作之后进入。中止会停止当前运行，并把排队消息退回编辑器。

## 上下文

活动分支提供对话历史。Pi 把会话条目转换为模型兼容的 user、assistant 和 tool-result 消息。

Pi 用其基础指令和发现的上下文文件构建系统提示词。请求还携带工具定义和技能描述。

完整的技能指令按需加载。扩展可以添加指令或转换上下文。

提示词模板在编辑器输入成为用户消息之前展开它。选中的文件、图片、粘贴的文本和 shell 输出都可以成为消息内容。

## 会话

持久化会话是 JSONL 文件。每个树条目有 ID 并引用其父条目。当前条目标识活动分支。

从较早的条目继续会在同一文件中创建另一个分支。Fork 和 clone 把选定的历史复制到新的会话文件。

模型上下文从活动分支重建。压缩会插入一个摘要条目，在后续模型请求中替代较旧的消息。原始条目仍保留在会话树中。

## 界面

交互模式在终端中渲染会话和 agent 事件。打印模式运行一条 prompt 并写出最终响应。JSON 模式把 agent 事件写成 JSONL。

RPC 模式在 stdin 上接受 JSONL 命令，在 stdout 上写出响应和事件。TypeScript SDK 在进程内创建并控制 agent 会话。

所有界面使用相同的 agent 和会话机制。

## 扩展与资源

扩展是加载进 Pi 进程的 TypeScript 模块。其工厂函数注册工具、命令、快捷键、提供商、事件处理器、渲染器和终端 UI。

技能提供按需的指令和配套文件。提示词模板提供可复用的消息文本。主题提供终端配色。Pi 包通过 npm 或 git 分发这些资源。

## 信任与权限

Pi 在加载项目设置和资源之前先解析项目信任。在信任决定和项目资源加载之后，Pi 加载上下文文件。启用的工具使用 Pi 进程的操作系统权限。扩展在该进程内执行。
